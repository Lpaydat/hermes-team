# Pattern: Context File Pre-Flight Check — Verify AGENTS.md and CLAUDE.md Before Feeding to Pipeline

Created 2026-08-10. Lesson from ngin setup session.

## Problem

Before feeding a spec into the workflow pipeline, the repo's context files (AGENTS.md, CLAUDE.md) must be correct and aligned with the project's actual state. Stale or wrong context files actively HARM the pipeline:

- **AGENTS.md said "SUPERSEDED, archived read-only"** — but ngin is active and about to be built. The architect would read this and think the project is dead.
- **CLAUDE.md was an empty template** — "Add your build commands here", "Add a brief overview". Zero useful information for pipeline agents.
- Both files were generic beads boilerplate with no ngin-specific content.

## Root Cause

These files were generated by `bd setup` (beads init) at project creation time. They contain generic tracker boilerplate. When a project changes state (un-archived, restarted, repurposed), the context files don't get updated.

psi's SUPERSEDED.md bled into ngin's AGENTS.md — likely a copy-paste or template artifact from the tau/pir consolidation.

## Pre-Flight Checklist

Before creating the `[spec]` or `[port]` card, verify:

1. **AGENTS.md**: Does it describe the CURRENT project? No "archived", "SUPERSEDED", or "read-only" language? Contains actual build/test commands?
2. **CLAUDE.md**: Is it filled in? No empty "Add your X here" placeholders? References the actual SPEC and ADRs?
3. **CONTEXT.md**: Does it exist? Is it consistent with AGENTS.md and CLAUDE.md? (CONTEXT.md is usually hand-written and correct — the generated files are the problem.)
4. **SPEC alignment**: Do AGENTS.md and CLAUDE.md reference the SPEC and ADRs correctly? Do they contradict any hard rules from CONTEXT.md?

## Fix Pattern

When context files are wrong:
1. Read CONTEXT.md and SPEC to understand the project's actual state and hard rules
2. Rewrite AGENTS.md to include: architecture summary, hard rules from CONTEXT.md, build/test commands, doc references
3. Rewrite CLAUDE.md to include: architecture overview, conventions, build commands, doc references
4. Both files should ALIGN with each other and with CONTEXT.md — no contradictions
5. Remove any "SUPERSEDED", "archived", "read-only" language
6. Remove generic boilerplate that doesn't apply to the project
7. Commit the fix BEFORE feeding the spec to the pipeline

## Example Fix (ngin, commit b5304623)

AGENTS.md before: 132 lines, starts with "SUPERSEDED, archived read-only", 100% generic beads boilerplate
AGENTS.md after: 50 lines, ngin architecture, 4 hard rules from CONTEXT.md, cargo build/test commands, key doc references

CLAUDE.md before: 77 lines, empty template with "Add your build commands here"
CLAUDE.md after: 45 lines, architecture overview, conventions, build commands, doc references

## General Rule

Pipeline agents read AGENTS.md and CLAUDE.md as project context. If these files lie about the project's state, agents make wrong decisions. Always pre-flight these files before starting a pipeline run.
