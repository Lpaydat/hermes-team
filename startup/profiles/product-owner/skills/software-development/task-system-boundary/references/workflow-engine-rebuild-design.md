## Key decisions

### Kanban-only (eliminate beads from engine)
- The bead-sync phase is fragile (patched 5+ times during livetests)
- Two stores = two failure modes
- You're not using beads' killer feature (git-sync via Dolt)
- When you build your own harness later, add beads back with proper lifecycle hooks

### No langgraph
- Tested: works as pure state machine with plain Python functions + SQLite persistence
- Wrong layer of abstraction: `invoke()` runs synchronously; agents run in separate gateway-managed processes for 30-60 min each
- Would need a bridge on top: one node = one dispatch + wait + read result = two state machines fighting

### JSON, not YAML
- JSON Schema validation natively
- Machine-generated by agents
- Kanban DB already uses JSON for card metadata
- No ambiguity (YAML has tabs-vs-spaces, implicit type coercion)

### Hybrid event model
- 5s poll of `task_events` table (12x faster than current 60s)
- 120s reconciliation poll (self-healing safety net)
- 4 trigger types: card lifecycle, bead state, git poll, manual

### State DB as cache
- Dedicated `workflow-state.db` (SQLite) for instance tracking + variable bindings
- Kanban DB is ground truth (card status = node status)
- `task_runs.metadata` is ground truth for outputs
- If state DB lost → engine rebuilds from kanban on restart

### Engine unaware of dynamic cards
- `kanban_complete` on the node card is the sole completion signal
- Profiles manage their own kanban_chains/loop_engine internals
- Engine sees: running → blocked → running → done

### 3 card-creation modes
- `template`: engine creates card directly (cron pattern)
- `delegate`: engine creates meta-card, profile creates children (PO dispatch pattern)
- `chain`: engine calls kanban_chains with rendered bodies (tech-lead pattern)

## ngin platform (existing)

The user's `~/workspace/ngin/` is 90% of this — Rust daemon with 8-phase tick loop, beads as source of truth, TUI dashboard, auto-unblock, crash recovery. Built for pi agents (subagent-runner spawn), not Hermes profiles (gateway-managed sessions). The rebuild should iterate incrementally on the current Hermes cron rather than port ngin wholesale — the user explicitly chose incremental over wholesale replacement.
